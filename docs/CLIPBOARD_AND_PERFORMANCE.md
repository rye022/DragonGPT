# v2.0.1 剪贴板修复与性能说明

剪贴板记录仍默认关闭。在头顶入口展开面板、启用记录后，随后复制的普通文字才会加入历史；已有条目在关闭记录后仍可复制。疑似凭据、图片、空白或过长文字不会记录。AI 分析仍需单独确认。

入口根据角色的显示区域定位，折叠时为 110 像素宽的按钮，展开时向上展开。拖动、尺寸变化、半身模式和显示器变化会更新位置；靠近屏幕顶部时缩短面板，并提供滚动条。

原实现把入口优先放在整个桌宠窗口下方；角色在窗口内还有气泡预留区。历史入库使用 `trimmed()`，导致缩进及末尾换行丢失。现在保留原始文本，只在检测和分类时使用需要的规范化处理。

Windows 上仅调用 `QClipboard::setText()` 后在同一进程读回，不足以证明其他应用可粘贴。回归测试复现了所有者 GUI 事件处理暂停时，独立进程读到空文本。现在只对本次复制的自有数据调用 `OleFlushClipboard()`，立即把数据写到系统；随后通过 `CF_UNICODETEXT` 校验实际文本。剪贴板占用时最多尝试 5 次，间隔 80 ms，并给出明确结果。保留行内空白、缩进、换行和 Unicode；Windows 原生文本的 CRLF 与 LF 按文本等价比较。

原生机制见 [Microsoft OleFlushClipboard 文档](https://learn.microsoft.com/en-us/windows/win32/api/ole2/nf-ole2-oleflushclipboard)。

性能改动：

- 动画之前每帧重采样 1209 × 1300 原图，随后缩小显示。现在缓存适合实际物理像素尺寸的帧，再计算局部动画；缩放和 DPI 变化时重建缓存。原图、动作图集和导出渲染函数保留。
- 剪贴板选中项从当前列表快照获取，复制不再查数据库。历史变化合并为一次刷新，折叠时延迟刷新；过期清理只有实际删除记录才通知界面。
- 原生剪贴板通知返回后再处理历史入库，避免在该通知内执行 SQLite 写入。
- 情绪衰减改由 Companion 的 100 ms 定时器管理，避免依赖桌宠帧率。专注页重复设置相同陪伴模式不触发额外动画刷新。
- 专注统计文字最多每 5 秒刷新，保存会话后立即失效。原有 MemoryStore 已缓存统计结果，因此这项主要减少重复格式化和 UI 更新，不能宣称减少了每秒 8 次 SQL。

后续建议：`memoryChanged` 仍会同时重建聊天记录、记忆列表和关系视图。可拆为领域信号、对隐藏页面采用延迟刷新，并对大量记忆采用增量模型；应先用大规模本地测试数据测量，再实施。语义检索已有按需加载和空闲释放，健康采样已在后台执行，无证据支持全面重写线程结构。

验证：新增 `dragon_clipboard_ui`，覆盖默认关闭/保留历史复制、原文、Unicode、独立进程读回（故意暂停所有者事件处理）、短暂占用重试、位置、屏幕顶部、缩放、半身及隐藏/显示。`dragon_ui_perf_probe` 在相同 Qt、DPI 和机器上，预热后分别测量 30 次同步 QWidget::grab 的中位数和 P95，覆盖 3 种大小、2 种视图、3 个动作。它衡量合成耗时，不代表整机 CPU 或云端延迟。

用户数据 schema 保持 7，不迁移或重写私人记忆、音色和 API 配置。不调用收费云端 API。
